# `.dsh/global/` — глобальный слой DeepSeek Harness

То, что обычно лежит в `~/.dsh` и потому не попадало в git: мост между DSH и
хуками проектов, запасной хук и утилита для навыков. Здесь оно версионируется,
чтобы на новой машине слой поднимался одной командой.

| Файл                        | Куда ставится      | Зачем                                                                          |
| --------------------------- | ------------------ | ------------------------------------------------------------------------------ |
| `hooks/dsh-hook.sh`         | `$DSH_HOME/hooks/` | маршрутизатор: находит хук текущего проекта и переводит его ответ в формат DSH |
| `hooks/claude-hooks.json`   | `$DSH_HOME/hooks/` | конфиг для плагина `@deepseek-ai/dsh-hooks-claude-code` (шаблон)               |
| `hooks/check-rules.sh`      | `$DSH_HOME/hooks/` | запасной хук: печатает `docs/` в проектах без своего скрипта                   |
| `bin/link-claude-skills.sh` | `$DSH_HOME/bin/`   | связывает `<проект>/.dsh/skills` с `.claude/skills`                            |
| `install.sh`                | —                  | установка перечисленного в `$DSH_HOME`                                         |
| `cordis.patch.example.yml`  | —                  | фрагмент патча профиля (установщик печатает готовый)                           |

## Установка

```bash
bash .dsh/global/install.sh              # в ~/.dsh
DSH_HOME=/путь bash .dsh/global/install.sh
```

Установщик копирует файлы, существующие сохраняет как `<имя>.bak-<время>` и
подставляет реальный путь в `claude-hooks.json`. Патч профиля он **не правит** —
печатает готовый блок:

```yaml
- insert:
    - id: hooks-claude-code
      name: '@deepseek-ai/dsh-hooks-claude-code'
      config:
        configPath: /Users/you/.dsh/hooks/claude-hooks.json
        defaultTimeoutMs: 300000
```

Запись обязана лежать внутри `insert:`: строка с неизвестным `id` только
предупреждает и не монтируется — именно из-за этого хуки когда-то не срабатывали
вовсе (см. `docs/DECISIONS.md`). HMR подхватывает правку патча на ходу,
перезапуск приложения не нужен.

## Что делает маршрутизатор

Конфиг хуков у плагина один на процесс, поэтому маршрутизатор — единственное
место, которое знает про конкретный проект. Порядок поиска: от рабочей папки
вверх по дереву `<проект>/.dsh/hooks/check-rules.sh` (DSH-нативный адаптер),
затем `<проект>/.claude/hooks/check-rules.sh` (как было в Claude Code), затем
глобальный `$DSH_HOOKS_DIR/check-rules.sh`. Нет скрипта — нет хуков.

Дальше он закрывает различия двух диалектов:

- `stop_hook_active` в DSH всегда `false`, поэтому состояние stop-цикла ведётся
  по факту: блокировали прошлую остановку — значит агент внутри самопроверки.
  Настоящее сообщение человека (событие `UserPromptSubmit`, текст которого не
  совпадает с последним `reason`) состояние сбрасывает.
- Голый stdout на `SessionStart`/`SubagentStart` в DSH выбрасывается — он
  заворачивается в `hookSpecificOutput.additionalContext`. Если скрипт уже
  вернул `hookSpecificOutput` (DSH-нативный адаптер), ответ отдаётся как есть.
- `@`-инклюды из `CLAUDE.md`/`AGENTS.md` DSH не разворачивает: файлы, которые
  существуют, перечисляются в контексте сессии.
- `SubagentStop` в DSH наблюдательный (заблокировать нельзя), поэтому по
  умолчанию пропускается; `DSH_HOOKS_RUN_SUBAGENT_STOP=1` включает его ради
  самих проверок.

Требуется `jq`: без него маршрутизатор и хуки проектов отключаются сами, сессия
не падает.

## Обновление и откат

Повторный `install.sh` обновляет файлы до версии из репозитория, старые уводит в
`.bak-*`. Откат — вернуть нужный `.bak-*` на место и, если требуется, убрать
запись `hooks-claude-code` из патча профиля: без неё плагин просто не
монтируется, остальное приложение работает как обычно.
